# ADR 0004: The API is OpenAI's audio API, completely, plus a small native one

Status: accepted, 2026-11-11

## Context

Every local speech server that has gained users implements OpenAI's
`/v1/audio/speech` and `/v1/audio/transcriptions`; Ollama chose the same. The
contract was taken from OpenAI's published OpenAPI document
(`openai/openai-openapi`, `openapi.yaml`: `/audio/speech` at line 602,
`/audio/transcriptions` at 698, `/audio/translations` at 1172) and checked by
running the official SDK, not by reading client code.

Partial implementations are where unmodified clients break. OpenAI's default
speech format is `mp3`; a server that only produces `wav` breaks every client
that does not set `response_format`.

## Decision

Implement the three audio endpoints in full, and say so precisely where
behaviour differs.

`POST /v1/audio/speech`

| Field | Behaviour |
|---|---|
| `response_format` | `mp3` (default), `opus`, `aac`, `flac`, `wav`, `pcm`. `wav` and `pcm` are native; the others are encoded by an `ffmpeg` binary if one is on `PATH`. Without ffmpeg the default becomes `wav`, and asking for `mp3` explicitly is a 400 that says why. |
| `pcm` | Always 24 kHz 16-bit mono, as OpenAI documents, resampled if the model's rate differs. `wav` keeps the model's native rate. |
| `voice` | A string, or an object with `id`. Unknown voices are a 400. |
| `speed` | 0.25 to 4.0, refused if the model does not declare `speed`. |
| `stream_format` | `audio` (default) or `sse` (`speech.audio.delta`, `speech.audio.done`). |
| `instructions` | Accepted and ignored, with an `X-Oaudio-Warning` header. |
| input length | Not capped at 4096 characters. |

`POST /v1/audio/transcriptions` and `/v1/audio/translations`

| Field | Behaviour |
|---|---|
| `file` | WAV natively; anything ffmpeg can read otherwise. |
| `response_format` | `json`, `text`, `srt`, `vtt`, `verbose_json`. |
| `timestamp_granularities[]` | `word`, `segment`; needs `verbose_json`, and `word` needs a model that declares it. |
| `stream` | Server-sent `transcript.text.delta` per segment, then `transcript.text.done`. |
| `language`, `prompt`, `temperature` | Passed to the engine; refused if the model does not support them. |

`GET /v1/models` lists only models a request would succeed against.

Extensions, all optional: `keep_alive` on any request (seconds or a duration
string, as in Ollama), `language` on speech requests, and response headers
`X-Oaudio-Model`, `X-Oaudio-Sample-Rate`, `Server-Timing: load;dur=…`.

Errors use OpenAI's shape (`{"error": {"message", "type", "param", "code"}}`)
so SDKs raise their own typed exceptions.

The native API under `/api` covers what OpenAI's has no words for: `pull`
(streamed progress), `models`, `catalog`, `show`, `voices`, `ps`, `stop`,
delete. See `docs/api.md`.

The default port is 11535. The address is set with `OAUDIO_HOST`.

## Consequences

- Clients with a hard-coded model name (`tts-1`, `whisper-1`) work through
  `OAUDIO_ALIASES="tts-1=apple-say,whisper-1=apple-speech"`.
- `verbose_json` segments include `tokens`, `avg_logprob` and similar fields
  with zero values when an engine does not report them, so typed clients can
  decode the object. They are placeholders, not measurements.
- ffmpeg is an optional runtime dependency, never linked. Its absence changes
  one default, visibly.
- There is no authentication and the server binds to loopback by default.
  Exposing it on a network is the operator's decision.

## Verified

The unmodified official OpenAI Python SDK (3.49.0), with only `base_url`
changed, passes 18 of 18 checks covering every row above:
`bench/sdk_conformance.py`, results in `docs/evidence.md`.

## Later additions

`diarized_json`, `/v1/audio/voices`, `/v1/realtime` (transcription sessions)
and two endpoints of Oaudio's own are described in ADR 0005.
